## 简介
本指南旨在为schooberAi项目提供从代码构建到生产环境部署的完整说明。项目基于MidwayJS框架开发，采用TypeScript编写，具备SSE流式响应、数据库持久化、会话管理等核心功能。本文将详细介绍如何编译、配置、运行和监控该应用，确保其在生产环境中稳定高效运行。

## 构建与启动流程

### 使用`npm run build`编译TypeScript代码
项目使用`mwtsc`工具进行TypeScript编译。`package.json`中的`build`脚本定义了编译命令：

```json
"build": "mwtsc --cleanOutDir"
```

该命令会：
- 清理输出目录（`--cleanOutDir`）
- 将`src/`目录下的TypeScript文件编译为JavaScript
- 输出到默认的构建目录（通常为`dist/`）

执行编译的步骤如下：
```bash
npm run build
```

编译完成后，项目根目录将生成`dist/`文件夹，其中包含所有编译后的JavaScript文件，可直接用于生产环境运行。

### 使用`npm start`启动生产环境应用
`package.json`中的`start`脚本定义了生产环境的启动命令：

```json
"start": "NODE_ENV=production node ./bootstrap.js"
```

该命令会：
- 设置环境变量`NODE_ENV=production`
- 使用Node.js直接运行`bootstrap.js`文件

`bootstrap.js`是应用的启动入口，其内容非常简洁：
```javascript
const { Bootstrap } = require('@midwayjs/bootstrap');
Bootstrap.run();
```

该文件通过MidwayJS的`Bootstrap`类启动整个应用，加载所有配置、中间件、控制器和服务。在生产模式下，框架会自动加载`config.default.ts`和`config.prod.ts`（如果存在）等配置文件。

## 生产环境配置

### 配置文件结构
项目使用MidwayJS的配置系统，配置文件位于`src/config/`目录下：
- `config.default.ts`：默认配置，适用于所有环境
- `config.unittest.ts`：单元测试环境专用配置
- （可选）`config.prod.ts`：生产环境专用配置，会覆盖默认配置

### 数据库连接配置
数据库连接配置在`src/configuration.ts`中通过TypeORM进行初始化。关键配置如下：

```typescript
createConnection({
  type: 'mysql',
  host: 'localhost',
  port: 3306,
  username: 'root',
  password: 'woshiGY3011',
  database: 'ai_mutil_message',
  extra: {
    connectionLimit: 10,
    waitForConnections: true,
    queueLimit: 0,
    connectTimeout: 60000,
    acquireTimeout: 60000,
    timeout: 60000,
  },
  maxQueryExecutionTime: 30000,
  entities: [
    __dirname + '/BussinessLayer/**/Domain/**/*.ts',
    __dirname + '/BussinessLayer/**/Domain/**/*.js'
  ],
  logging: ['error', 'warn'],
  synchronize: false,
});
```

**生产环境配置建议：**
1. **不要在代码中硬编码数据库凭证**：应通过环境变量注入
2. **调整连接池大小**：根据应用负载和数据库能力设置`connectionLimit`
3. **关闭实体同步**：`synchronize: false`，避免生产环境意外修改数据库结构
4. **合理设置日志级别**：仅记录`error`和`warn`，避免日志过多影响性能

### 外部服务API密钥配置
项目通过请求体中的`variableMaps`对象传递大模型配置（如API密钥、模型URL等）。例如，在`AgentService`中：

```typescript
const { ak, ApiUrl, cwdFormatted } = LLMConfigParam
```

**安全建议：**
- API密钥应在客户端通过安全方式获取，不应在服务端硬编码
- 建议在前端或网关层进行API密钥的注入和管理
- 可通过环境变量或配置中心统一管理外部服务凭证

## 进程管理与部署最佳实践

### 使用PM2进行进程管理
PM2是Node.js应用推荐的进程管理工具，可实现应用的守护、负载均衡、自动重启和监控。

**安装PM2：**
```bash
npm install -g pm2
```

**使用PM2启动应用：**
```bash
pm2 start bootstrap.js --name schooberAi --node-args="--max-old-space-size=4096"
```

**PM2配置文件（ecosystem.config.js）示例：**
```javascript
module.exports = {
  apps: [
    {
      name: 'schooberAi',
      script: './bootstrap.js',
      instances: 'max',
      exec_mode: 'cluster',
      env: {
        NODE_ENV: 'production',
      },
      max_memory_restart: '1G',
      autorestart: true,
      watch: false,
    },
  ],
};
```

### 使用Docker进行容器化部署
Docker化部署可确保环境一致性，简化部署流程。

**Dockerfile示例：**
```dockerfile
FROM node:18-alpine

WORKDIR /app

COPY package*.json ./
RUN npm ci --only=production

COPY . .

RUN npm run build

EXPOSE 7001

CMD ["node", "bootstrap.js"]
```

**docker-compose.yml示例：**
```yaml
version: '3'
services:
  app:
    build: .
    ports:
      - "7001:7001"
    environment:
      - NODE_ENV=production
      - DB_HOST=db
      - DB_PORT=3306
      - DB_USER=root
      - DB_PASSWORD=your_secure_password
    depends_on:
      - db

  db:
    image: mysql:8.0
    environment:
      - MYSQL_ROOT_PASSWORD=your_secure_password
      - MYSQL_DATABASE=ai_mutil_message
    ports:
      - "3306:3306"
    volumes:
      - db_data:/var/lib/mysql

volumes:
  db_data:
```

## 性能优化建议

### 调整数据库连接池大小
在`src/configuration.ts`中，`extra.connectionLimit`字段控制MySQL连接池的最大连接数。建议根据以下因素调整：
- **应用并发量**：高并发应用需要更大的连接池
- **数据库性能**：确保数据库能承受连接池的最大连接数
- **服务器资源**：每个连接都会消耗内存和CPU

**建议值：**
- 小型应用：5-10
- 中型应用：20-50
- 大型应用：50-100+

### 启用适当的日志级别
在生产环境中，应避免记录过多日志，以免影响性能和磁盘空间。

在`src/configuration.ts`中，TypeORM的日志级别已配置为：
```typescript
logging: ['error', 'warn'],
```

**建议：**
- 仅在调试时开启`'query'`和`'schema'`日志
- 使用`@midwayjs/logger`进行应用日志记录，可配置日志级别和输出格式
- 定期轮转和归档日志文件

### 优化SSE流式响应
项目使用SSE（Server-Sent Events）实现流式响应，在`AgentController.run`方法中设置响应头：
```typescript
res.writeHead(200, {
  'Content-Type': 'text/event-stream',
  'X-Accel-Buffering': 'no',
  'Cache-Control': 'no-cache',
  'Connection': 'keep-alive'
});
```

**优化建议：**
- 确保反向代理（如Nginx）正确配置以支持SSE
- 在Nginx中设置`proxy_buffering off;`
- 监控长连接对服务器资源的影响

## 健康监控与日志分析

### 应用健康检查
可通过以下方式实现健康检查：
1. **HTTP健康检查端点**：创建`/health`或`/ping`路由返回200状态码
2. **PM2监控**：使用`pm2 monit`或`pm2 list`查看应用状态
3. **Docker健康检查**：在Dockerfile中添加`HEALTHCHECK`指令

### 性能指标监控
项目已内置简单的性能监控中间件`report.middleware.ts`：

```typescript
@Middleware()
export class ReportMiddleware {
  resolve() {
    return async (ctx: Context, next: NextFunction) => {
      const startTime = Date.now();
      const result = await next();
      ctx.logger.info(`Report in "src/middleware/report.middleware.ts", rt = ${Date.now() - startTime}ms`);
      return result;
    };
  }
}
```

该中间件记录每个请求的响应时间（RT），可用于分析性能瓶颈。

**增强监控建议：**
- 集成APM工具（如Elastic APM、Datadog）
- 监控数据库查询性能，关注`maxQueryExecutionTime`
- 设置慢查询告警
- 监控内存使用情况，防止内存泄漏

### 日志分析
- **日志位置**：默认输出到控制台，可通过配置输出到文件
- **日志格式**：包含时间戳、日志级别、消息内容
- **分析工具**：可使用ELK（Elasticsearch, Logstash, Kibana）或类似工具进行集中分析
